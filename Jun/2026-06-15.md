# TIL

## 소제목: 네트워크 기초, 주소 체계, 네트워크 장비 이해

### 새로 배운 내용

#### 주제 1: 네트워크란 무엇인가
- 네트워크는 데이터를 송수신하는 장치들이 서로 연결되어, 정해진 통신 규칙에 따라 정보와 자원을 공유할 수 있게 하는 시스템이다.
- 단순히 케이블이나 Wi-Fi가 있는 것만으로 네트워크가 완성되는 것은 아니다.
- 연결된 장치들이 서로 데이터를 주고받을 수 있어야 네트워크라고 할 수 있다.
- 네트워크를 사용하면 문서, 이미지, 영상, 데이터베이스 같은 정보를 공유할 수 있고, 프린터나 파일 서버 같은 자원도 함께 사용할 수 있다.
- 인터넷은 전 세계의 여러 네트워크가 연결된 거대한 네트워크이다.
- 즉, 인터넷은 네트워크의 한 종류이자 가장 큰 규모의 네트워크라고 볼 수 있다.

#### 주제 2: 네트워크의 구성 요소
- 네트워크를 구성하려면 데이터를 주고받는 장치, 네트워크 인터페이스, 연결 매체, 주소, 네트워크 장비, 통신 규칙이 필요하다.
- 장치에는 PC, 스마트폰, 서버, 프린터, 라우터, 스위치 등이 있다.
- 네트워크 인터페이스에는 유선 LAN 카드, Wi-Fi 모듈, 가상 NIC 등이 있다.
- 연결 매체에는 랜 케이블, Wi-Fi, 광케이블 등이 있다.
- 주소에는 IP 주소와 MAC 주소가 있다.
- 통신 규칙에는 TCP/IP, HTTP, DNS 같은 프로토콜이 있다.
- 브라우저에서 웹사이트에 접속할 때도 DNS, IP 주소, 포트, NIC, 스위치, 라우터, 서버, 애플리케이션이 순서대로 관여한다.

#### 주제 3: 노드와 호스트
- 노드는 네트워크에서 데이터를 생성, 수신, 전달하는 장치나 지점이다.
- PC, 스마트폰, 서버, 라우터, 스위치, 프린터, IoT 장치 모두 노드가 될 수 있다.
- 호스트는 네트워크에 연결되어 서비스를 사용하거나 제공하는 최종 장치이다.
- PC, 스마트폰, 웹 서버, DB 서버는 호스트에 해당한다.
- 호스트는 노드에 포함되는 개념이다.
- 노드는 중간에서 데이터를 전달하는 장비까지 포함하지만, 호스트는 주로 출발지나 목적지 역할을 하는 최종 장치를 의미한다.

#### 주제 4: IP 주소와 MAC 주소
- 네트워크에서 노드를 구분하려면 주소가 필요하다.
- IP 주소는 네트워크 상의 논리적 위치를 나타내는 주소이다.
- MAC 주소는 NIC에 부여된 데이터 링크 계층 주소로, 같은 네트워크 구간에서 장치를 식별하는 데 사용된다.
- IP 주소는 최종 목적지가 어느 네트워크에 있는지 찾기 위한 주소이다.
- MAC 주소는 현재 네트워크 구간에서 다음 장비에게 실제로 전달하기 위한 주소이다.
- 라우터는 IP 주소를 보고 다른 네트워크로 보낼 경로를 결정한다.
- 스위치나 AP는 MAC 주소를 보고 같은 LAN 안에서 프레임을 전달한다.
- 라우터를 지날 때마다 MAC 주소는 다음 구간의 장비에 맞게 바뀌지만, 목적지 IP는 최종 서버에 도착할 때까지 유지된다.

#### 주제 5: ARP
- ARP(Address Resolution Protocol)는 IP 주소에 대응하는 MAC 주소를 알아내는 프로토콜이다.
- 같은 LAN 안에서 어떤 장치에 데이터를 보내려면 목적지 IP뿐 아니라 실제 프레임을 보낼 MAC 주소도 필요하다.
- 예를 들어 노트북이 같은 Wi-Fi에 있는 프린터로 데이터를 보내려면, 프린터의 IP 주소를 기준으로 ARP를 통해 MAC 주소를 알아낸다.
- 이후 Ethernet 또는 Wi-Fi 프레임의 목적지 MAC에 해당 장치의 MAC 주소를 넣어 전달한다.

#### 주제 6: 네트워크 범위에 따른 분류
- 네트워크는 통신 범위에 따라 PAN, LAN, MAN, WAN으로 나눌 수 있다.
- PAN(Personal Area Network)은 개인 주변의 가까운 장치들을 연결하는 네트워크이다.
- 예를 들어 스마트폰과 무선 이어폰, 스마트워치, 무선 마우스 연결이 PAN에 해당한다.
- LAN(Local Area Network)은 집, 사무실, 학교처럼 제한된 공간 안에서 여러 장치를 연결한 내부 네트워크이다.
- LAN은 인터넷과 같은 의미가 아니며, 인터넷이 없어도 같은 로컬 네트워크 안에서 노드끼리 통신하면 LAN이다.
- MAN(Metropolitan Area Network)은 도시, 캠퍼스, 여러 건물처럼 LAN보다 넓고 WAN보다는 좁은 범위를 연결하는 네트워크이다.
- WAN(Wide Area Network)은 도시, 국가, 대륙처럼 지리적으로 멀리 떨어진 네트워크들을 연결하는 광역 네트워크이다.
- 인터넷은 대표적인 WAN이다.

#### 주제 7: LAN, WLAN, VLAN
- LAN은 가까운 공간의 장치들을 연결하는 내부 네트워크이다.
- LAN의 장점은 가까운 장치끼리 빠르게 통신하고 프린터, 파일 서버, 인터넷 회선 같은 자원을 공유할 수 있다는 점이다.
- WLAN(Wireless Local Area Network)은 LAN을 랜선 대신 Wi-Fi 같은 무선 신호로 제공하는 네트워크이다.
- WLAN은 이동성과 설치 편의성이 좋지만, 신호 간섭, 보안, 속도 변동, 음영 지역, AP 과부하에 주의해야 한다.
- VLAN(Virtual Local Area Network)은 하나의 물리 네트워크를 여러 개의 독립된 네트워크처럼 논리적으로 나누는 기술이다.
- VLAN은 보안 강화, 트래픽 감소, 관리 편의성, 비용 절감에 도움이 된다.
- VLAN은 브로드캐스트 도메인을 나누어 불필요한 브로드캐스트 트래픽이 퍼지는 범위를 제한한다.

#### 주제 8: NIC와 MAC Address
- NIC(Network Interface Card)는 컴퓨터나 네트워크 장비가 유선 또는 무선 네트워크에 연결되어 데이터를 송수신할 수 있게 하는 인터페이스이다.
- 유선 LAN, Wi-Fi, Bluetooth, Docker나 VM에서 생성되는 가상 NIC도 각각 네트워크 인터페이스가 될 수 있다.
- MAC 주소는 NIC에 부여된 물리적 식별자이다.
- 하나의 장치에 여러 NIC가 있다면 여러 MAC 주소를 가질 수 있다.
- NIC는 운영체제의 네트워크 스택과 드라이버의 지시에 따라 IP 패킷을 Ethernet 또는 Wi-Fi 프레임으로 감싸고, 이때 출발지 MAC과 목적지 MAC이 포함된다.

#### 주제 9: 리피터와 허브
- 리피터는 약해진 네트워크 신호를 다시 증폭하거나 재생해서 더 먼 거리까지 전달하는 장치이다.
- 리피터는 물리 계층 장비로, MAC 주소나 IP 주소, TCP 포트, HTTP 내용을 보지 않는다.
- 허브는 여러 장치를 하나의 네트워크에 연결하고, 들어온 데이터를 모든 장치에게 전달하는 장비이다.
- 허브는 목적지를 판단하지 않고 모든 포트로 신호를 뿌린다.
- 이 때문에 불필요한 트래픽이 많고, 보안에 불리하며, 충돌이 발생하기 쉽다.
- 현대 LAN에서는 허브보다 스위치를 주로 사용한다.

#### 주제 10: 스위치와 브릿지
- 스위치는 같은 네트워크 안에서 MAC 주소를 보고 데이터를 필요한 장치에게만 전달하는 장비이다.
- 허브가 모두에게 보내는 장비라면, 스위치는 목적지에게만 보내는 장비이다.
- 스위치는 MAC Address Table을 통해 어느 MAC 주소가 어느 포트에 연결되어 있는지 학습한다.
- 목적지 MAC 주소를 알고 있으면 해당 포트로만 프레임을 전달한다.
- 목적지 MAC 주소를 모르면 Unknown Unicast Flooding을 수행할 수 있다.
- 브로드캐스트는 목적지가 모든 장치인 통신이고, Flooding은 특정 목적지 MAC을 모르기 때문에 여러 포트로 보내는 동작이다.
- 브릿지는 두 개 이상의 LAN 세그먼트를 연결하고, MAC 주소를 기준으로 필요한 트래픽만 전달하는 장비이다.
- 현대 네트워크에서는 독립 장비로서의 브릿지보다 스위치가 더 많이 사용된다.

#### 주제 11: 라우터
- 라우터는 서로 다른 네트워크를 연결하고, IP 주소를 보고 패킷이 갈 다음 경로를 결정하는 장비이다.
- 스위치는 같은 LAN 내부에서 MAC 주소를 보고 프레임을 전달한다.
- 라우터는 다른 네트워크로 나갈 때 IP 주소와 라우팅 테이블을 보고 다음 홉을 결정한다.
- 라우터는 최종 목적지까지 한 번에 보내는 장비가 아니라, 지금 위치에서 다음으로 보낼 라우터나 인터페이스를 결정하는 장비이다.
- 라우팅 테이블은 라우터가 참고하는 길 안내표이다.
- 라우팅 테이블에는 목적지 네트워크 대역, Prefix, Next Hop, Outgoing Interface, Metric 같은 정보가 들어간다.
- 라우터는 일반적으로 목적지 IP와 가장 구체적으로 일치하는 경로를 우선 선택한다.
- 경로를 찾지 못하면 `0.0.0.0/0` 같은 기본 경로로 보낼 수 있다.

#### 주제 12: 동적 라우팅
- 동적 라우팅은 라우터끼리 경로 정보를 교환해 라우팅 테이블을 자동으로 구성하는 방식이다.
- OSPF는 회사 내부망이나 데이터센터 내부에서 라우터끼리 빠르게 경로를 공유할 때 사용된다.
- RIP은 단순한 홉 수 기반 라우팅 프로토콜이지만 한계가 있어 주로 교육용이나 소규모/구형 환경에서 언급된다.
- BGP는 인터넷 사업자, 클라우드, 대규모 네트워크 간 경로 교환에 사용된다.
- OSPF가 조직 내부 라우팅에 가깝다면, BGP는 조직과 조직 사이의 라우팅에 가깝다.

#### 주제 13: 게이트웨이와 공유기
- 게이트웨이는 서로 다른 네트워크나 프로토콜 사이에서 통신을 가능하게 하는 출입구 역할을 한다.
- 현재 네트워크에 속하지 않은 목적지로 데이터를 보내야 할 때 기본 게이트웨이로 전달한다.
- 가정에서는 공유기가 기본 게이트웨이 역할을 하는 경우가 많다.
- 게이트웨이는 라우터처럼 동작할 수도 있고, NAT, 필터링, 프로토콜 변환, API 중계 같은 기능을 포함할 수도 있다.
- 라우터는 목적지 IP를 보고 다음 경로를 결정하는 장비이고, 게이트웨이는 서로 다른 네트워크 사이의 출입구라는 의미가 강하다.
- 가정용 공유기는 라우터, 스위치, 무선 AP, NAT, 기본 게이트웨이 기능을 합친 장비이다.

#### 주제 14: 실제 통신 흐름
- PC가 인터넷에 있는 웹 서버로 HTTP 요청을 보내면 먼저 브라우저가 HTTP 요청 데이터를 만든다.
- 전송 계층에서는 TCP 헤더가 붙고, 네트워크 계층에서는 IP 헤더가 붙는다.
- 이후 NIC가 현재 구간에서 보낼 Ethernet 또는 Wi-Fi 프레임을 만든다.
- 외부 서버로 가는 요청이라면 목적지 MAC은 최종 서버의 MAC이 아니라 기본 게이트웨이인 라우터의 MAC이다.
- 스위치는 목적지 MAC을 보고 라우터가 연결된 포트로 프레임을 전달한다.
- 라우터는 프레임을 벗기고 IP 패킷을 확인한 뒤, 라우팅 테이블을 기준으로 다음 홉을 결정한다.
- 라우터는 다음 구간용 새 프레임을 만들고, 이 과정이 여러 라우터에서 반복된다.
- 서버에 도착하면 서버 NIC가 목적지 MAC을 확인하고 프레임을 받은 뒤, IP 헤더와 TCP 헤더를 제거해 HTTP 데이터를 웹 서버 애플리케이션에 전달한다.
- 핵심은 IP 패킷은 최종 서버까지 이동하고, Ethernet/Wi-Fi 프레임은 각 네트워크 구간마다 새로 만들어진다는 점이다.

#### 주제 15: 네트워크 디버깅 관점
- 네트워크 장애를 볼 때는 아래 계층부터 위로 올라가며 확인하는 것이 좋다.
- 먼저 물리적인 연결이 되어 있는지 확인한다.
- 그 다음 IP 주소가 유효한지 확인한다.
- 목적지로 갈 수 있는지 확인한다.
- 포트가 열려 있는지 확인한다.
- 마지막으로 애플리케이션이 응답하는지 확인한다.
- `ping`은 목적지까지 네트워크 연결이 되는지 확인할 때 사용한다.
- `curl`은 HTTP 응답을 정상적으로 주는지 확인할 때 사용한다.
- `nslookup`은 도메인이 어떤 IP로 해석되는지 확인할 때 사용한다.
- `netstat`, `ss`는 특정 포트가 열려 있는지 확인할 때 사용한다.
- `traceroute`는 목적지까지 어떤 라우터들을 거치는지 확인할 때 사용한다.
